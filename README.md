# AI 学习计划助手

> 2026 华北五省大学生计算机应用能力大赛 · 天津赛区 · 赛道一（垂直应用场景的创新设计与开发）

**一句话定位**：市面上的 AI 学习工具，输出是一段文本，用完就丢。我们把它做成**有语义、有状态机、可被机器校验的格式**（`.studyplan`），于是计划才能被持续执行、修订和协商。

## 5 分钟跑起来

```powershell
# 1. 装依赖（Node ≥ 22.18、pnpm ≥ 10）
pnpm install

# 2. 配置（可选，不配也能跑）
Copy-Item .env.example .env      # 然后填 LLM_API_KEY

# 3. 跑测试，确认环境没问题
pnpm test                        # 应为 670 passed / 0 failed
```

**不配 `.env` 也能完整体验**：所有涉及模型的功能都带本地兜底，只是措辞和出题不再因人而异。界面会如实标注走的是哪条路（「AI 综述」vs「系统综述」）。

### 三个入口

| 入口 | 命令 | 说明 |
|---|---|---|
| **命令行** | `pnpm plan check examples/demo.studyplan` | 最快验证格式与引擎，不需要起服务 |
| **API** | `pnpm --filter @sp/server start` | → http://127.0.0.1:8787 ，浏览器打开根路径能看到端点清单 |
| **App（浏览器）** | `pnpm --filter @sp/mobile run web` | → http://localhost:8081 |
| **App（手机）** | `pnpm mobile` | 手机装 Expo Go，与电脑同一 Wi-Fi。脚本会先探一遍服务端再启动 |

> **演示/录屏前**：在「文件」页打开**演示模式**。它让所有模型调用走本机，
> 一次网络请求都不发。要防的不是断网（断网会立刻失败并降级），而是
> 「网通着但模型 API 连不上」——那种情况会一路等到 90 秒超时。
>
> **想演示「隔了几天回来结账」**：文件页 →「时间」→「固定日期」→ 点〔今天〕
> → 再点〔模拟隔了 5 天回来〕。演示当天没法真的等一天，这个按钮就是为此存在的。

### 手机上验一遍落盘

落盘有**两份平台实现**：原生（`expo-file-system`，手机用）和 web（`localStorage`，浏览器用）。
端到端脚本只能验到后者，所以原生那一份必须上真机。

```powershell
pnpm mobile        # 会在终端打出二维码；也可以把打印出的 exp://<IP>:8081 手输进 Expo Go
```

打开 App 后按这个顺序看：

| 步骤 | 应该看到 | 说明 |
|---|---|---|
| 1 | 底部四个标签，能正常切 | 原生模块加载成功 |
| 2 | 切到「文件」页 | 后端显示 **设备文件系统**（若是「浏览器存储」就是打错包了） |
| 3 | 看路径 | 形如 `file:///data/user/0/<包名>/files`，**不是** cache 目录 |
| 4 | 看状态 | **已保存到设备**，右边没有红字 |
| 5 | 看正文 | 开头是格式说明，含 `studyplan/v1`，几十行 |
| 6 | 去「今日」打勾一项，回「文件」 | 正文变了、状态仍是「已保存到设备」 |
| 7 | **杀掉 App 再打开**（不是刷新） | 计划还在，改动还在 |

第 7 步是唯一真正**从设备读回来**的一步。前六步的正文也已经是盘上的内容——
每次写完都会立刻读回来核对，读回来的和写下去的不一致就报「存储层可能有问题」，
不会拿刚序列化的字符串冒充成功。

## 现在能跑通什么

**完整闭环已经打通**：访谈 → 生成计划 → 打勾 + 报实际用时 → 引擎识别偏差 → 协商调整 → 写回计划。

真实模型跑一遍（实测数据）：

1. **访谈**：模型动态出题，5 题后判断信息够了。每题都带「为什么问这个」。
2. **生成计划**：12 个任务、覆盖 3 个能力点，耗时 20–40 秒。
   - 独立复查结果：0 条校验错误、**0 个任务排在学生说没空的日子、0 个排进考试周**、周预算与时段容量一致。
3. **打勾一项**并填实际用时（20 分钟的活干了 120 分钟）。
4. **引擎**算出「实际耗时是预估的 6 倍」，连同下游连锁影响给出 3 条重排建议。
5. **模型**把结果讲成人话：

> 上一轮里「查清蓝桥杯省赛与 ACM 校赛的赛制、题型与评分规则」这件事实际花的时间是预估的 **6 倍**，把原定的时段整个吃掉了，后面四步只能依次往后挪一周。因为你每周只有一个 60 分钟时段、一次只能推一件事，所以是**整条链顺延，不是某一环单独延**。

6. **落盘**：切到「文件」标签页，能看到设备上那份 `.studyplan` 的原文
   （重新生成后是 v3、139 行、3.4 KB），刷新页面后计划仍在，
   并且每次变更都留下了上一版的整份快照（用于回滚）。
7. **工具调用**：在「资源」页点「按计划内容找资料」，系统按计划里的能力点和
   目标原话去检索，把查到的资料**挂到对应的任务上**——任务卡折叠态就会出现
   「资料 N」胶囊。能联网时还会实时拉 Codeforces 赛程，卡片上标**实时**；
   拉不到就只显示蓝桥杯 / CCPC / ICPC 的官网入口，**不会给一个猜的截止日**。
8. **导出**：「文件」页可以把计划导成 Markdown（贴进聊天窗口）或 `.ics`
   （导进手机日历，赛事截止提前一天提醒）。
9. **隔了几天回来会结账**：启动时如果距上次打开 ≥1 天、而且确实有任务过期，
   会进「结账」页——列出这段时间本该完成却没打勾的任务，默认按「都没做」算，
   学生只勾出其实做完的。确认后**一条命令**写回：放回待排池 / 压缩到接下来几天 /
   先不动。放弃用 `skipped` 而不是删除。

顺带一提：`goal.statement` 保留学生原话，模型改不动——这是代码强制的，不是提示词自觉。

## 目录结构

```
.
├─ packages/
│  ├─ shared/          ← 唯一真相源，无平台依赖（Hermes 也能跑）
│  │  └─ src/plan/     ← schema（格式定义）/ commands（命令层）/ engine（自适应引擎）/ io
│  │  └─ src/llm/      ← 四个 LLM 契约 + 本地兜底 + 输出校验
│  │  └─ src/tools/    ← 资料库 + 确定性检索（**不碰网络**，所以断网也能用）
│  ├─ llm-client/      ← OpenAI 兼容薄客户端（需要 fetch，故与 shared 分开）
│  ├─ storage-node/    ← 原子写文件（temp + rename）
│  └─ env-node/        ← .env 加载
├─ apps/
│  ├─ server/          ← Fastify，持密钥 + 唯一真的发 HTTP 的地方
│  │  └─ src/tools/    ← codeforces.ts：实时赛程（免费公开接口，无需密钥）
│  └─ mobile/          ← Expo（SDK 57），三个标签 + 二级屏（访谈/复盘/目标/日历/任务编辑/结账）
│     └─ src/storage/  ← 计划落盘。原生用 expo-file-system，web 用 localStorage（分平台文件）
├─ tools/plan-cli.ts   ← 命令行入口
├─ examples/demo.studyplan  ← 格式的活文档，同时是测试输入
├─ docs/               ← 技术方案 / 开发计划 / 测试指南
└─ .dev/               ← 开发脚本（截屏、端到端、诊断），不属于产品
```

**分层的一条铁律**：`packages/shared` 里不许出现 `fetch`、`window`、Node API。
移动端断网时要能用本机逻辑把复盘算出来，这是产品的降级路径，不是容错加分项。

## 让 App 走真实模型

App **默认自动找服务端**：它从 Metro 的地址推断——Expo Go 连的那台机器就是开发机，服务端也在同一台上，于是自动拼出 `http://<开发机IP>:8787`。手机上通常不用配。

两种例外：

- **浏览器 + 静态产物**：没有 Metro 地址可推断，会走本机兜底。要连服务端就在 `apps/mobile/.env` 里写：
  ```
  EXPO_PUBLIC_SP_SERVER=http://127.0.0.1:8787
  ```
  然后重新 `expo export`。⚠️ 变量名必须以 `EXPO_PUBLIC_` 开头，且必须写成 `process.env.EXPO_PUBLIC_X` 这个**字面形式**（用可选链会静默失效）。
- **服务端在别的机器上**：同上，地址换成那台机器的局域网 IP。

- [x] **计划真实落盘**：每次变更写回设备上的 `.studyplan`，并留下上一版的整份快照。

- [x] **三处动效**：勾选（填充淡入 + 划掉）、展开面板长高、进度数字滚动。
  划掉是「第二份透明文字 + 有色装饰线」，所以折行的标题也划得准
- [x] **工具调用（主动获取信息）**：内置资料库检索（纯本地，断网可用）+
  实时抓取 Codeforces 赛程（真的发 HTTP，无需密钥）。
  模型**不能新增资源**——它写的 `resources` 一律丢掉并报出丢了几条
- [x] **端到端闭环**，并有脚本真的点一遍验证（含刷新后计划仍在、「找资料」、导出、结账）
- [x] **一个时钟，两种模式**：调试模式的日期由设置给（想设哪天设哪天，且不会自己走），

- [x] **回归结账**：隔了 ≥1 天再打开时自动发现「有几项已经过期」，一屏问清

  叙述先说本机那版，模型返回后替换；**模型写出的数字必须全在事实白名单里**，
  否则整段退回本机措辞
- [x] **导出 md / ICS**：生成器在 `packages/shared`（纯函数，23 项测试盯着折行与转义），

  触控区从 26×22 变成远超 44）；编辑页可改标题/备注/类型/标记/时长/日期/前置/资料，
  **除标题和备注外没有任何自由文本输入**（日期点月历、时长用 ±15，
  「最早可安排日」复用同一张月历加一个「正在设定」开关）；
  任务标记（`Task.tags` 存 id，目录在 `plan/tags.ts`，为以后的「时间标记影响排期」
  和「自定义颜色」留了扩展点）。一次保存 = 一条命令 = 一次写盘
- [x] **复盘**（v0.4）：一屏六块，从上往下就是一次对话——
  ①这周发生了什么（**本机算的事实，不过模型**，所以可以先显示也不可能被编）
  ②先问一句（0–2 题，只在答案会改变建议时才出现）③我建议这样调（方向）
  ④帮你写好的卡片 ⑤现在的安排（**和今日页同一套日历与任务卡**）⑥之前的复盘（折叠）。
  完成率、超预估、过期、下周怎么调，全在引擎里算，模型只负责说人话。
  **触发完全手动**：入口组件 `<ReviewEntry />` 与位置解耦（`useReviewLauncher()`），
  将来要加主动提示，只是多一个弹窗去调**同一个** `openReview()`
- [x] **审核建议卡**：每张卡可勾掉（不要）／划掉（这次先不管）／点进去改（改成你想要的样子）。
  **点进去预填的是「建议值」而不是「当前值」**——做错了界面看着完全正常，
  但「帮你写好」这件事就一点没发生，所以端到端里有一条专门盯它的断言。
  **不设条数上限**（典型 2–3 张）：上限只会砍掉最后几条，而学生不知道少了什么
- [x] **跟 AI 说说**（v0.4）：右下角常驻入口，一句话进去三种结局——
  说清楚了给待确认卡；说不清楚**先问**（最多 2 轮）；做不到的**明说做不到**并写清原因。
  它和复盘产出的是**同一个 `Proposal` 类型**、应用走**同一条** `plan.applyAdjustments`，
  模型给的每一条都要过 `validateProposal`（编的 id、过去的日期、撞上考试周的日期全部拒掉，
  **理由是人话**）。
- [x] **撤销**：应用完通知里带〔撤销〕，靠 `plan.restore` 装回快照（不是反向再发一条命令）。
  **只活到下一次改动之前**——任何新改动都会让它消失，否则学生会把中间那次一起撤掉。
  撤销本身也是一次正常写入（版本 +1）
- [x] **学生档案住进计划文件**（`plan.profile`）：目标 / 截止日 / 水平 / 每周可投入时间 /
  学习日 / 薄弱点 / 要避开的整段。**重开 App 还在、换设备跟着走**，
  「跟 AI 说说」和找资料都有依据。校验不过就当没有，**不让一份坏档案把整份计划读不出来**
- [x] **多目标**（v0.5）：一个计划里可以有好几条**各自有截止日**的线
  （「蓝桥杯省赛」和「ACM 校赛」的日期不一样）。
  **引擎一行都没改**——它本来就是目标无关的（从不读 `plan.goal`，
  按里程碑排期、按里程碑报风险），「目标」在数据里就是里程碑，所以**格式也没动**。
  新增的是表达：
  **跟 AI 说一句「我还想加一条线」** → AI 回一张卡
  `新目标「搜索与贪心冲刺」· 截止 12月28日 · 6 项 · 合计 7 小时 · 排进 10/24–10/31`
  → 勾上就落地（目标 / 能力点 / 任务 / 连线一次成）。
  **模型不许算日期**：它把新任务的 `scheduledFor` 留空，日期由引擎排好再写回卡片，
  所以卡上那行是「真的排进去了」的证据，排不下时会说「排不进现在的时段」。
  复盘**按每条线分开说**：紧的是哪条就改哪条自己的截止日，方向那句话会点名
  （「『蓝桥杯省赛』（12月31日 截止）可能赶不上」）

## 已知的坑（照着做能省几小时）

| 现象 | 原因 / 做法 |
|---|---|
| PowerShell 里跑 pnpm 满屏红字 | 那是 pnpm 回显脚本命令，被 PowerShell 当成错误流。**不是失败**，看退出码 |
| `ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY` | 非交互环境装依赖需要 `confirmModulesPurge: false`（已在 `pnpm-workspace.yaml` 里），必要时加 `--no-frozen-lockfile` |
| 端口 8787 被占用 | 多半是上一次的服务端还在跑。**它跑的是旧代码**，会造成「改了没生效」，先杀掉 |
| 中文显示成乱码 | `chcp 65001` |
| **改了代码里的中文，全变成 `绠楁硶` 这种乱码** | 别用 PowerShell 读写源码（`Get-Content -Raw` + `Set-Content` 会把 UTF-8 当 GBK 读一遍再写回去，**静默毁掉整个文件**）。改代码用编辑工具，按行改。想在终端里搜中文用 `Select-String`（只读，安全）。这一条已经踩过**四次**，最近一次毁掉的是 1277 行的 `plan-store.tsx`，**整份重写**才救回来 |
| 装不了依赖、报 npm 缓存 EPERM | 用 pnpm（store 在工作区内），或 `npm --cache .npm-cache` |
| 手机扫码连不上 | 多网卡时 Expo 可能挑错网卡（本机有 WLAN / VirtualBox / Radmin 三张）。直接用 `pnpm mobile`——它问路由表拿默认路由那张网卡的地址，并把没选中的列出来 |
| 手机连上了，但 AI 一直「（本机）」 | 多半是 App 推断出的 API 地址不对。`pnpm mobile` 启动前会先探 `http://<IP>:8787/health`，探不通会直接告诉你 |
| **真机上怀疑没落盘** | 切到「文件」标签页：后端应是「设备文件系统」，路径形如 `file:///data/user/0/<包名>/files`，状态「已保存到设备」。**杀掉 App 重开**再确认一次。失败时卡片会区分「文件内容读不出来」（手改敲错，给覆盖按钮）和「存储不可用」（存储层问题，给重试按钮）|
| **新加了路由，`router.push('/xxx')` 报 TS2345** | expo-router 的 typedRoutes 用的是**生成出来的**类型（`.expo/types/router.d.ts`），而 `expo export` **不会**重新生成它。跑一次 `expo start`（几秒即可，然后关掉）就更新了 |
| **加了一个新目录（如 `src/app/task/`）之后，`expo start` 生成的路由类型仍然是错的** | 路由缓存是脏的：生成出来的清单会把 `src/components/*`、`packages/shared/src/plan/*` **当成路由**，而新目录里的路由根本没进去。加 `--clear` 重来一次就干净了。**判断依据：清单里出现 `/../components/...` 这种路径就是脏的** |
| **手机上一直弹「Cannot connect to Expo CLI」** | 那是**开发期**的 HMR 警告（Metro 的 `/hot` websocket），不是 App 出错，Expo 只在「曾经连上过、后来断了」时才弹它。先看 `pnpm mobile` 打出来的「Metro HMR 回环通」在不在——在就说明 Metro 是好的，**在手机上重新加载一次**即可。单独诊断：`node .dev/probe-hmr.mjs <你的IP>` |
| **从本机探自己的局域网地址（`http://192.168.x.x:端口`）超时** | 这个环境下就是不通，**和 Metro、和手机都无关**：实测 8081/8787 从本机都超时，连一个什么都没监听的端口也超时（Node 和 PowerShell 一样）。所以**别拿它当判据**——会误报。手机走的是另一条路（真实网卡进出）。要验的是手机能不能刷出画面 |
| **真机上弹「Each child in a list should have a unique "key" prop」，而你的 `.map` 明明都写了 key** | 那是 RN 的 `ScrollView` 干的：它在原生上**无条件**跑一遍 `React.Children.toArray`，而 `toArray` 会把没有 key 的直接子节点克隆并标成 `_store.validated = 2`——Fabric 正是为这个条件报警告。**web 上永远看不到**（RNW 的 ScrollView 不跑那句），所以别指望端到端或截图能发现它。规矩：`app/` 里一律用 `@/components/scroll-body` 的 `ScrollBody`，不要直接用 `ScrollView`（有静态检查盯着）。详见 `docs/技术方案.md` §9.18 |
| **`pnpm test` 数量对不上** | 当前是 670。数量变化本身不是问题，**有 fail 才是** |
| **以为 git 是退路** | `.git` 里只有一个 `init` 提交，**停在 v0.3 之前**——最近几轮改动一条都不在里面，`git checkout` 回去会得到一份几个月前的代码。要真当退路，先提交一次 |

## 改代码之前请先看这一段

`docs/技术方案.md` 的 **§9.6 / §9.7** 记了四条**踩过的**教训，都是类型检查和单测发现不了的。摘要：

1. **给模型的示例不是文档，是模板。** 示例里把任务的 12 个字段写全，模型就每个任务都写满，生成耗时从 30 秒涨到 90 秒以上。
2. **提示词里一个歧义短语能让产品跑到别的领域。** 「中文学习规划助手」被模型读成「规划怎么学中文」。
3. **模型会把学生原话"润色"掉。** 提示词写了「保留原话」，它照样改——这类不变量必须由代码强制。
4. **「接口返回 200」不等于「结果是对的」。** 端到端脚本要用共享层的校验器独立复查模型产出。

以及一条架构级的：**别让两个功能靠 id 巧合连接**。曾经「访谈的答案写进哪个档案字段」是靠题目 id 猜的，结果接上模型后答案一条都写不进去，而且不报任何错。

**还有几条设计决策，改之前请先商量**：

- **引擎算，模型说**。日期、时长、依赖、护栏全部由 `engine.ts` 决定，模型只是表现层。模型幻觉再离谱也污染不了计划文件。
- **学生说过的约束必须结构化**。`Task.notBefore`、`constraints.blackouts` 都是为此存在——自由文本模型读得懂、规则层读不懂，降级时就丢了学生的意图。
- **手动改期默认上锁**。「我说了不算」比「排得不优」伤得多。
- **一屏一个主要操作**；深色模式下必须也好看（比赛投影用深色）。
