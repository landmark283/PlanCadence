**已经抓到三个真实缺陷**，来源不同，这个对比本身很说明问题：

| #   | 缺陷                                                                                         | 谁发现的               |
| --- | ------------------------------------------------------------------------------------------ | ------------------ |
| 1   | `plan.restore` 在 `execute` 里手动追加一次历史，`applyCommand` 又统一追加一次 → history 重复，违反「只增不减」          | **自证测试**           |
| 2   | 重排写成 `earliest = 依赖日 > earliest ? 依赖日+1 : earliest`，把「今天」和「依赖日」混为一谈 → 依赖恰好排在今天时，后置任务被排到同一天 | **自证测试**           |
| 3   | 学生的「等期中考试周之后再安排」只写在 `notes` 自由文本里，规则层读不懂，于是把任务排到了期中**之前**                                  | **LLM 的 cautions** |

第 3 条尤其值得记下来：

- 它证明 LLM 层的 `cautions` 不是装饰——规则算不出来的语义矛盾，它真能看出来。
- 但**不能依赖它**：离线降级（`--engine-only` / 断网 / 没配 Key）时没有 LLM，
  这个漏洞就无人兜底。所以修复方式是**给这类意图补结构化表达**（`Task.notBefore`），
  由规则层强制执行，而不是把提示词写得更啰嗦。
- 判断依据：**「我说了不算」比排得不优严重得多**。学生明说过的意愿被系统无视，
  比系统排了个次优方案伤害大得多。

（另外两处同类保护：`pinned` 守护「学生手动改过的日期」，30% 护栏守护「别一次挪太多」。）

**两条关键验证结论**：

- **Node 类型剥离可以穿透 pnpm workspace 符号链接**（realpath 落在 `packages/shared` 而非 `node_modules` 内），所以后端零构建步骤就能直接跑 TS。
- **Metro 能解析显式 `.ts` 后缀的 workspace TS 源码**；`studyplan/v1` 常量确实出现在 bundle 与 SSR 生成的 HTML 里（不是被静默 tree-shake）。

### 1.3 已踩的环境坑（记下来避免重复踩）

| 坑                         | 现象                                                            | 结论                                                                                                                                                          |
| ------------------------- | ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| npm 缓存越界                  | `EPERM ... AppData\Local\npm-cache\_cacache\tmp\...`          | **不是网络问题**。用 pnpm（store 在工作区内），或 `npm --cache .npm-cache`                                                                                                   |
| Vite/vitest               | Vite 8 在 Windows 上 `child_process.exec('net use')` → EPERM    | 测试改用 `node --test --experimental-test-isolation=none`。**注**：该约束是沙箱策略产物，当前 danger-full-access 已放开 `child_process`；仍保留 node:test，因为它零依赖、进程内，不受策略变化影响          |
| Node ESM 解析               | 无扩展名 import 直接崩                                               | shared 内部相对导入**必须写 `.ts` 后缀**（已配 `allowImportingTsExtensions`）。⚠️ 这条对 Metro 有影响，P3 首次跑 Expo 时要重点验证                                                          |
| Metro + pnpm              | ——                                                            | **SDK 52+ 自动处理**，不要手写 `watchFolders`/`nodeModulesPaths`；有就删掉再 `expo start --clear`                                                                          |
| 无 Android SDK             | `adb` 不存在，`ANDROID_HOME` 为空                                   | 真机调试**只能靠 Expo Go 扫码**；要模拟器就得装 Android Studio（不建议为此花时间）                                                                                                     |
| pnpm 重建 node_modules      | 新增 workspace 包时报 `ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY` | 写进 `.npmrc` **不生效**——pnpm 10+ 读 `pnpm-workspace.yaml`（已加 `confirmModulesPurge: false`）。另外 CI 环境下还要加 `--no-frozen-lockfile`，否则撞 `ERR_PNPM_OUTDATED_LOCKFILE` |
| mobile 继承 expo 的 tsconfig | 跟随进 `shared` 报 `TS5097`（不允许 `.ts` 后缀）                         | `apps/mobile/tsconfig.json` 必须自己加 `allowImportingTsExtensions: true` + `noEmit: true`。它继承的是 `expo/tsconfig.base`，**不是**我们的 `tsconfig.base.json`             |
| 模板 CSS module 类型缺失        | `Cannot find module './x.module.css'`                         | `expo-env.d.ts` 本由首次 `expo start` 生成；提前手写 `/// <reference types="expo/types" />` 即可让没跑过 dev server 的机器也通过 tsc                                               |

### 1.4 一条刻意加的护栏

`packages/shared` 会同时跑在 **Hermes（RN）** 和 **Node（后端）** 上，所以：

- 主 `tsconfig.json` **排除 `*.test.ts` 且不引入 `@types/node`** → 编译期就禁止在共享源码里用 Node API
- `tsconfig.test.json` 单独给测试开 `types: ["node"]`

`pnpm typecheck` 跑两个配置。这是「shared 保持平台无关」的机器保证，不是靠自觉。

### 一条刻意的产品决策：CLI 不伪造复盘记录

`plan apply` 默认**不写** `reviews` 条目，需要 `--record-review` 才写。

原因：`reviews[].loadFeedback` 是学生的主观自评（"这次是轻松还是吃力"），
命令行无从得知。第一版实现自动写了一条「本期计划 1 项、完成 0 项」，
而引擎会把它读成"学得很吃力"并建议缩减目标——**学生其实只是这周任务本来就少**。
复盘记录应当由复盘界面在拿到学生真实反馈后写入。
