# 功能补充与debug
人使用程序之后，发现了功能不足，或者bug，或者说要做某些修改，就把要做的事写到这里。由ai读取之后，完成开发，通过验收之后，把版本更新记录到 '版本更新.md' 当中去。
这里不负责记录到底做了哪些修改，只是人与ai沟通的一个渠道。

## 功能不足

### 功能上，复盘应该是由人主动发起的
复盘有两种情况，一种是人主动约定好，要复盘，此时ai应该提醒这个人去进行复盘。
另一种情况，是用户主动提出复盘。

那么我们的复盘就只需要一个入口：由人来主动发起，并且在这个过程中，人可以自己编写任务卡片，随时修改局部的目标，甚至是修改最终目标。

### 主界面交互性弱的问题
任务卡片的调整按钮按了没有用，你可以告诉我你现在是怎样设计
## 业务bug
ai在思考的时候，前端界面是静止的。我们可以参考常见的实现，用流在界面上实时显示出ai的思考链，并且点击显示的位置，可以展开完整的流。   最终这里的流只是为了让用户等待的时候不那么无聊，所以ai的思考链我们当然不会记录下来（如果后端有需要，后端当然是可以记录对话日志的，这里说的是前端）
