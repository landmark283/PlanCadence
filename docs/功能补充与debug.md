# 功能补充与debug

人使用程序之后，发现了功能不足，或者bug，或者说要做某些修改，就把要做的事写到这里。由ai读取之后，完成开发，通过验收之后，把版本更新记录到 '版本更新.md' 当中去。
这里不负责记录到底做了哪些修改，只是人与ai沟通的一个渠道。

---

## 待办

### 让 AI 交流更顺畅（前端）

ai在思考的时候，前端界面是静止的。我们可以参考常见的实现，用流在界面上实时显示出ai的思考链，并且点击显示的位置，可以展开完整的流。最终这里的流只是为了让用户等待的时候不那么无聊，所以ai的思考链我们当然不会记录下来（如果后端有需要，后端当然是可以记录对话日志的，这里说的是前端）

**状态：可行性已实测，未实现。**
`deepseek-flash` **确实**会流式输出 `reasoning_content`（实测 258 个 SSE chunk，
`reasoning_content` 出现 258 次）。原生端能流：`expo/fetch` 在 SDK 57 里存在，
`FetchResponse.body` 是真的 `ReadableStream`，不用加依赖、不用 XHR hack。
一个要注意的坑：实测里 `max_tokens: 256` 会被思考链**全部吃光**，
`content` 长度为 0——参数给太小会看到「想完了，然后什么都没有」。

## 已完成

（已完成的事项写进 `docs/版本更新.md`，不在这里留副本。）

- **时间显示问题** —— v0.2。两种模式（调试模式日期由设置给且不自己走 /
  正常模式由服务端 `GET /time` 给）、服务端统一时钟、`SP_TODAY`/`SP_TZ`、
  隔了 ≥1 天自动结账、去掉版本管理界面。详见 `docs/版本更新.md`。

- **主界面交互性弱** —— v0.3。日历屏（月历与首页周条**是同一个组件**）、
  任务卡「点=展开 / 长按=进编辑页」（那个 26×22 的「调整」小字删掉了）、
  编辑页（标题/备注/类型/标记/时长/日期/前置/资料/删除，除标题和备注外
  **没有一个自由文本输入**）、任务标记框架、以及 `task.edit` 缺失的字段校验。
  详见 `docs/版本更新.md` 与 `docs/日历与任务编辑方案.md`。

- **卡片不能拖拽** —— **决定不做，已从待办里划掉。** 今日页卡片的顺序不进引擎，
  在那儿拖拽没有语义目标；跨天移动本质是一个离散的选择，用编辑页里点格子更准。
  更要紧的是拖拽要引手势库，而本项目的自动化验证全在 web 上，**等于没有回归保护**。

- **复盘应该由人主动发起** —— v0.4。复盘从常驻 tab 变成今日页右上角的一个入口，
  **完全由人手动触发**。整条链路：一屏六块（本机算的事实 → 0–2 个条件问句 →
  建议的方向 → 帮你写好的卡片 → 现在的安排 → 折叠的复盘日志）；
  建议卡可勾掉 / 划掉 / 点进去改（**预填的是建议值**，不是当前值）；
  不设条数上限；一条命令原子写回；可撤销（只活到下一次改动之前）。
  同时新增「跟 AI 说说」（一句话改计划，含糊的先问、做不到的明说、断网不假装）
  和跟着计划文件走的学生档案（重开 App 它还记得你）。
  **主动提示那一半按你的意思没做**，但入口组件与位置解耦
  （`<ReviewEntry />` + `useReviewLauncher()`），将来要加只是多一个弹窗
  去调同一个 `openReview()`。
  详见 `docs/版本更新.md` 的 v0.4 与 `docs/复盘与AI协商方案.md`。

- **A 事件和 B 事件截止时间不一样，也要能用复盘排期** —— v0.5。
  一个计划里可以有好几条各自有截止日的线（赛事 / 考试 / 一门课），
  复盘按每条线分开说：**紧的是哪条就改哪条自己的截止日**，方向那句话会点名。
  同时「跟 AI 说说」可以**一句话新增一条线**（目标 / 能力点 / 任务一次成），
  新任务的日期由引擎排好再写回卡片。
  **格式和引擎都没动**：「目标」在数据里就是里程碑，而引擎从来不读 `plan.goal`
  （它按里程碑排期、按里程碑报风险）——多目标在引擎里早就成立，缺的只是表达。
  详见 `docs/版本更新.md` 的 v0.5 与 `docs/技术方案.md` §9.16。
