# 第一部分 · 做出来是什么样

## 1.1 今日页多了一个「日历」

「本周安排 · 点日期切换」这一行，右边多一个**日历**按钮：

```
  本周安排 · 点日期切换                    〔 日历 〕
  ┌────┬────┬────┬────┬────┬────┬────┐
  │ 一 │ 二 │ 三 │ 四 │ 五 │ 六 │ 日 │
  │ 5  │ 6  │ 7  │ 8  │ 9  │ 10 │ 11 │
  │ ▬▬ │    │ ▬▬ │    │    │ ▬▬ │ ▬▬ │
  └────┴────┴────┴────┴────┴────┴────┘
```

点它进入**日历屏**：一个整月的格子，格子里面和上面的周条**长得一模一样**
（日号 + 一条 3pt 的负载条，选中是浅色底、今天用主色数字、全做完的那天是绿条）。

```

   │    │    │ ▬▬ │    │    │ ▬▬ │ ▬▬ │
   ├────┼────┼────┼────┼────┼────┼────┤
   │  6 │  7 │  8 │  9 │ 10 │ 11 │ 12 │

   │ ▬▬ │ ▬▬ │    │    │ ▬▬ │    │ ▬▬ │

  10月14日 周三 · 2 项 · 1 小时 30 分        〔 + 新任务 〕
  ┌──────────────────────────────────────┐
```

- 格子点一下 = 选中那天，下面换成那天的任务卡。**卡片是同一张卡片**——

- 「回到今天」回到时钟给出的今天（调试模式下就是被固定的那天，不会乱跑）。

## 1.2 任务卡：点开、长按改

现在的样子（这就是你说「按了没有用」的那个东西）：

```
  ☐  复习：背包三变体回忆默写              调整     ← 26×22 的浅色小字
     〔待办〕〔复习〕〔45 分钟〕〔上锁〕
```

改成：

```
  ☐  复习：背包三变体回忆默写                    ⌄     ← 点这里展开
     〔待办〕〔复习〕〔45 分钟〕〔上锁〕〔重点〕
```

- **整块内容区（标题 + 胶囊 + 备注）是展开/收起按钮**，高度远超 44pt；
  勾选框是它的**兄弟**，不是子元素——所以点勾选框只会勾选，不会顺带展开。
- **长按同一块区域 = 直接进编辑页**。长按和点击不会互相误触发：
  `react-native-web` 的 `PressResponder` 里明确写着长按之后不调 `onPress`
  （`isPressCanceledByLongPress`），原生端 `Pressability` 同规则；
  两端的阈值也都是 500ms 左右。
- 右边那个 `⌄` 是**真的折角箭头**，展开时会转 180°。它是提示，不是按钮。
- 展开后第一行就是编辑入口：

```
  ☐  复习：背包三变体回忆默写                    ⌃
     〔待办〕〔复习〕〔45 分钟〕〔上锁〕〔重点〕
     ────────────────────────────────────
     〔 编辑这一项 〕   也可以长按卡片直接进来   ← 长按看不见，得留个看得见的
     状态  〔待办〕〔进行中〕〔卡住了〕〔已跳过〕
     预估  〔15〕〔25〕〔45〕〔60〕〔90〕〔120〕
```

「编辑这一项」这个胶囊**不是多余的**：长按对读屏用户完全不可见，
一个只有长按的入口等于没有入口。它同时也解决可发现性。

## 1.3 编辑页：一切点选，不让你敲日期

长按卡片（或点「编辑这一项」）进 `/task/[id]`：

```
  ‹ 返回            编辑任务
  ─────────────────────────────────────────
  这张卡是什么
  ┌──────────────────────────────────────┐
  │ 标题                                  │
  │ [复习：背包三变体回忆默写             ]│   ← 只有标题和备注是自由文本
  │ 备注                                  │
  │ [┌────────────────────────────────┐  ]│
  │  │ 这题上次错在边界，再做一遍      │  ]│
  │  [└────────────────────────────────┘  ]│
  │ 类型  〔阅读〕〔练习〕〔动手〕〔复习〕〔自测〕│
  │ 标记  〔重点〕〔等考完再做〕〔想问老师〕〔易错〕│
  └──────────────────────────────────────┘

  要多久
  ┌──────────────────────────────────────┐
  │            45 分钟                    │   ← 当前值，大字
  │ 〔15〕〔25〕〔45〕〔60〕〔90〕〔120〕    │

  │ 〔今天〕〔明天〕〔待排池〕              │
  │     一    二    三    四    五    六    日
  │   ┌────┬────┬────┬────┬────┬────┬────┐
  │   │ 19 │ 20 │[21]│ 22 │ 23 │ 24 │ 25 │   ← 直接点格子，就是选日期
  │   ├────┼────┼────┼────┼────┼────┼────┤
  │   │ 26 │ 27 │ 28 │ 29 │ 30 │ 31 │  1 │
  │   └────┴────┴────┴────┴────┴────┴────┘
  │ 〔‹ 上月〕〔回到今天〕〔下月 ›〕          │
  │ 〔上锁〕 手动改期后引擎不再自动挪动它      │
  └──────────────────────────────────────┘

  这项要等谁
  ┌──────────────────────────────────────┐
  │ 〔01 背包手推 5 遍〕〔图论入门〕〔+ 加一个〕│
  │ 已经排在它后面的任务不出现在这里——        │
  │ 选它会形成一个环，计划会拒绝。            │
  └──────────────────────────────────────┘

  资料
  ┌──────────────────────────────────────┐
  │ 已挂上  〔动态规划入门 · 文章〕〔取消挂载〕│
  │ 还没挂  〔背包九讲〕〔洛谷题单〕          │
  └──────────────────────────────────────┘

  危险
  ┌──────────────────────────────────────┐
  │ 〔删除这一项〕  ← 点一下变成「真的删掉？」 │
  │ 有 2 项依赖它，删掉后那 2 项的前置会被清空。│
  └──────────────────────────────────────┘
  ─────────────────────────────────────────
                        〔 取消 〕〔 保存 〕
```

**一条硬规则：这一屏除了标题和备注，没有任何一个自由文本输入。**

| 要设的东西 | 怎么设 |
|---|---|
| 日期 | 点月历里的格子（和首页周条同一套格子） |
| 「最早可安排日」 | **同一张月历**，上面切换「正在设定：排期 / 最早可安排日」 |
| 时长 | 档位胶囊 + `−15 / +15` 微调，当前值大字显示 |
| 类型 / 标记 / 前置 / 资料 | 点选胶囊 |
| 上锁 | 一个胶囊 |

为什么「最早可安排日」不再用文本框（上一版我打算用 `2026-11-09` 那种输入）：

1. 一个日期输入框要求学生在脑子里做格式转换，而**旁边就有一张月历**；
2. 键盘会顶起半屏，正好盖住下面要看的东西；
3. 手打日期是「输错了要等报错才知道」，点格子不可能点出一个不存在的日期。

一张月历、一个「正在设定什么」的开关，比两个分开的控件更好理解，
也少了一个要单独校验的输入。

**保存是「一次动作 = 一条命令」。** 改标题又改了日期，仍然只发一条。

## 1.4 标记：这一版只搭框架，实现尽量简单

- 现在卡片上能出现 `〔重点〕〔等考完再做〕〔想问老师〕〔易错〕` 这四个**内置标记**，
  编辑页里点一下就加上，卡片上看得见，日历里的卡片也看得见。
- 任务上存的是**标记 id 的数组**（`task.tags: ['tag_focus']`），不是文字。
  这一点是整个框架的全部意义：以后要加「时间标记（影响排期）」或者
  「标记自定义颜色」，改的是**标记目录**和引擎，**任务上的数据不用动**。
- 当前版本**不做**：新建自定义标记、改颜色、改文案、让标记影响排期。
  目录里目前只有内置四条。

# 第二部分 · 已经定下来的判断

你认可的那些照旧，这里只列结论：

1. **日历是独立一屏**（不是今日页里展开）。
2. **日历格子里不写「周几」**（列头已有）；其余部分和首页周条是**同一个组件**。
3. **改期只走编辑页**一条路径，不做「在日历上点一天就挪过去」的隐藏模式。
4. **不做拖拽**。卡片顺序不进引擎（拖了系统不认），跨天移动本质是离散选择；
   更要紧的是它要引手势库，而我们的自动化验证全在 web 上，等于没有回归保护。
   替代品是编辑页里点格子。建议把待办里「卡片不能拖拽」这条划掉。
5. **一次保存 = 一条命令**（需要放宽 `task.edit` 的字段范围）。
6. **顺手修 `task.edit` 没有字段校验这个洞**（见 3.2）。

按你新指示改掉的两处：

7. ~~展开区那个胶囊是唯一入口~~ → **长按卡片是主入口**，胶囊作为可见/无障碍的入口保留。
8. ~~「最早可安排日」用文本输入~~ → **和排期共用同一张月历**（见 1.3 的三条理由）。

我自己拿的两个主意，都不难改，你不认可就说：

- **编辑页不设「状态」**。完成/进行中/卡住仍然只在卡片上那个勾选框和展开区改。
  理由：`task-card.tsx` 文件头已经写下「完成只走勾选框，避免两个入口改同一个字段」，
  而 `task.setStatus` 还额外挡着「前置未完成不许标完成」——搬进编辑页就是第二个实现。
- **标记目录放在计划文件里（`plan.tags`），当前是空数组**。
  内置四条写死在代码里；将来学生自定义的标记有地方落，而任务上引用的永远是 id。
  这个字段现在没有写入者，但它是被读取的（`resolveTags` = 内置 + 自定义）。

# 第三部分 · 详细实现方案

## 3.1 先做纯函数层（`packages/shared`）

原则：**能测的逻辑不放 `apps/mobile`**。mobile 没有测试脚本，
根 `pnpm test` 只跑 shared / server / llm-client / env-node / storage-node。
所以日历运算、id 生成、字段 diff、标记解析全部放 shared。

### 新增 `packages/shared/src/plan/calendar.ts`

```ts
addMonths(day: string, n: number): string        // 1月31日 +1 月 → 2月28/29 日（夹到月末）
monthOf(day: string): string                     // '2026-10'
monthLabel(day: string): string                  // '2026 年 10 月'
monthGridDays(anchor: string): string[]          // 固定 42 天，周一起（与 startOfWeek 同口径）
inMonth(day: string, month: string): boolean
```

- 全部按 **UTC 正午** 运算，和既有 `lib/dates.ts` 同一套办法，不碰本地时区。
- `monthGridDays` 固定返回 42 天（6 行）而不是「够用就少一行」：
  行数一变整屏高度就跳，而学生正在看的就是这个高度。
- 夹月末（1/31 → 2/28）是必须的：直接 `Date.UTC(y, m+1, 31)` 会溢出到 3 月 3 日。

### 新增 `packages/shared/src/plan/ids.ts`

```ts
newTaskId(existing: readonly string[]): string   // 't_07'
```

- 扫出已有的 `t_<数字>`，取最大值 +1，补到两位。与 `planner.ts` 产出的
  `t_01` 风格一致（同一个格式里既有的命名）。
- 不用时间戳/随机数：`applyCommand` 是纯函数，调用方也不该为了建一条任务
  去读时钟。碰撞时向后顺延，有上限。
- 结果必须满足 schema 的 `Id` 正则 `^[a-z][a-z0-9_]{0,31}$`（有测试盯着）。

### 新增 `packages/shared/src/plan/task-patch.ts`

```ts
type TaskDraft = { title; notes; type; tags; estimateMin; scheduledFor; pinned; notBefore; dependsOn; resourceIds };
draftOf(task: Task): TaskDraft
taskPatch(before: Task, draft: TaskDraft): Partial<...> | null   // null = 没有变化
```

为什么值得单独一个模块：

1. **「哪些字段真的变了」必须只有一处实现**。编辑页、将来的 AI 协商页（B）
   都要发这种 patch；两处各写一遍 diff，迟早会出现「AI 能改但我改不了」
   或者「界面说改了、实际没改」。
2. 它是纯函数，能在 shared 里被测。写在组件里的 diff 测不到。
3. **「改期默认上锁」这条规则落在它身上**：`scheduledFor` 变了 → patch 带上
   `pinned: true`（沿用 `task.reschedule` 从 v0.1 就有的规则），学生可以在
   编辑页把「上锁」再点掉。命令层不替学生猜，界面侧的决策留在界面侧的纯函数里。

## 3.2 命令层：放宽 `task.edit`、补上校验

`packages/shared/src/plan/commands.ts`：

```ts
| {
    type: 'task.edit';
    at: string;
    taskId: string;
    patch: Partial<
      Pick<Task,
        | 'title' | 'notes' | 'type' | 'tags' | 'estimateMin'
        | 'scheduledFor' | 'pinned' | 'notBefore'
        | 'dependsOn' | 'resourceIds' | 'milestoneId'>
    >;
  }
```

**刻意不含 `status` / `actualMin` / `difficulty`**：见第二部分里「编辑页不设状态」的理由。

`case 'task.edit'` 改成：

```ts
case 'task.edit': {
  const t = find(cmd.taskId);
  if (!t) return { error: `未找到任务 ${cmd.taskId}` };
  const parsed = Task.safeParse({ ...t, ...cmd.patch });
  if (!parsed.success) {
    return { error: `修改不合法：${parsed.error.issues[0]?.message ?? '未知'}` };
  }
  Object.assign(t, parsed.data);
  return `任务「${t.title}」已修改`;
}
```

- 覆盖全部字段（空标题、负时长、非法日期、超长备注、不认识的任务 id）。
- `dependsOn` 指向不存在的任务、以及成环，仍由 `validatePlan` 兜底拒绝
  （那是跨实体的判断，单个 `Task` 的 zod 看不见）。
- `task.reschedule` / `task.setPinned` / `task.setNotBefore` **保留不动**：
  语义单一（点一下就挪/锁/设下限），而且 `task.reschedule` 的隐式上锁
  已经写进 `docs/技术方案.md` 并被测试盯着。

### 为什么还是「一次保存 = 一条命令」

取消版本管理之后，这个决定**变得更硬**了，而不是变得随便。真实理由是三条：

1. **半改状态没有退路**（这一条现在最严重）。四条命令中间任何一条被拒
   （字段非法、前置成环、日期踩到不该踩的地方），前面三条已经生效了。
   学生看到的是「标题改了、日期没改」，而**现在没有任何回滚能把这一次编辑
   整体撤掉**——他得自己想起来改了哪几个字段、各自原来是什么。
   一条命令则是要么全成要么全不成。
2. **history 里一次编辑变成四行**，回放时看不出这是一次动作
   （而 history 是文件里给人和 AI 读的记录，文件页能直接翻到）。
3. **四次写盘 + 四份 `versions/` 快照**，而学生只是改了个标题。
   快照是磁盘层的安全网，不该被一次编辑动作打四遍。

## 3.3 标记（tags）框架

### 格式改动（**不升 schema 版本**）

`packages/shared/src/plan/schema.ts`：

```ts
export const Task = z.object({
  ...
  /** 学生自己打的标记。存的是 id，不是文字——见 plan/tags.ts */
  tags: z.array(Id).default([]),
  ...
});

export const PlanFile = z.object({
  ...
  /** 标记目录。内置的在代码里，这里放学生自定义的（当前没有界面写入，先留空） */
  tags: z.array(Tag).default([]),

```

- 两处都是 `.default([])`，所以**旧文件照常解析**，`schema` 仍是 `studyplan/v1`，
  不需要迁移。这是这个格式里既有的做法（`Review.loadFeedback` 等都是这么加的）。
- 第一次写盘之后，示例文件每个任务的 `tags: []` 会出现在文件里——这是对的，
  格式应该把「有这个东西」明说出来。

### 新增 `packages/shared/src/plan/tags.ts`

### 我拒绝加的东西（记下来免得以后有人补上）

**不加 `kind: 'time'` / `payload` 这类字段。** 你说以后可能有「时间标记，影响排期」，
但今天没有任何代码会读它——一个永远不被读的字段是最容易腐烂的东西
（`commands.ts` 里已经为这条道理删过一次按墙上时钟判断的守卫）。

框架的扩展点其实不在字段上，而在**任务存的是 id 这件事**上：

- 加「时间标记」= 给 `Tag` 加字段 + 让 `engine.ts` 读它；
- 加「自定义颜色」= 往 `plan.tags` 里写一条；
- 加「自定义标记」= 给 `plan.tags` 写一个界面。

三种扩展都**不需要动任务上的数据**。这就是框架，而它是靠引用方式建立的，
不是靠预留空字段。

- `planner.ts` 的提示词**不改**：生成的计划里标记为空，学生自己打。

### 改 `components/card.tsx`

加 `SectionHeader({ children, right })`：一行，左边是既有的 `SectionLabel`，
右边是动作位。以及 `SectionAction({ label, onPress, accessibilityLabel })`。

`SectionAction` 单独存在是为了把教训固化成代码：**动作必须有一个真的 44pt
触控区**（外层 `Pressable` 给 `minHeight: touchTarget`，里面才是 `Chip`）。

就不需要每个调用点重新记得这件事。

## 3.6 任务卡头部 `components/task-card.tsx`

结构（关键是**勾选框与可点区是兄弟**）：

```tsx
<View style={styles.head}>
  <CheckControl ... />                          {/* 自己处理点击 */}
  <Pressable                                   {/* 点 = 展开，长按 = 编辑 */}
    accessibilityRole="button"
    accessibilityState={{ expanded }}
    accessibilityLabel={expanded ? `收起「${title}」` : `展开「${title}」的调整`}
    accessibilityHint="长按可以直接编辑这一项"
    onPress={onToggleExpand}
    onLongPress={onOpenEditor}
    style={styles.body}
  >
    <View style={styles.titleRow}>
      <View style={styles.title}>…（含划线的副本）…</View>
      <Animated.Text style={{ transform: [{ rotate: chevron }] }}>⌄</Animated.Text>
    </View>
    <View style={styles.metaRow}>…胶囊…</View>
    {notes}
  </Pressable>
</View>
```

- **不做「Pressable 套 Pressable」**：`react-native-web` 上的点击会冒泡、
  原生靠 responder 系统，两边行为不一致——`task-card.tsx` 文件头已经记着这条。
  把勾选框放到外层，嵌套这件事在构造上就不存在。
- 长按阈值**不传 `delayLongPress`**，用两端的默认值（都是 500ms 左右）。
- `accessibilityHint` 把长按说给读屏听，但**真正的无障碍入口是那个胶囊**：
  hint 只是提示，用语音控制/开关控制的用户不一定用得上。
- 文件头里「元信息胶囊不可点」那段要改写成事实：胶囊现在落在可点区里，
  点它们就是展开，而**它们自己不带 onPress**，所以没有两个动作抢同一个手势。
- 箭头用 `Animated` 的 `rotate` 插值（`useNativeDriver: true`），
  和现有的划线副本同一个套路，不引入新依赖。

## 3.7 编辑页 `app/task/[id].tsx` + `app/task/new.tsx`

- 草稿状态 `useState<TaskDraft>`，初值 `draftOf(task)`；`taskPatch` 为 `null`
  时「保存」禁用（也就不会产生一条什么都没改的命令）。
- 保存：`apply({ type: 'task.edit', taskId, patch })` → `router.back()`。
  失败（命令层拒绝）时**不返回**——`notice` 显示在别处等于没提示。
  所以编辑页自己也挂 `NoticeBanner`。
- 新建：`apply({ type: 'task.add', task: {...} })`，id 用
  `newTaskId(plan.tasks.map(t => t.id))` **在保存那一刻**生成
  （不是打开页面时——两次打开会撞 id）。
  默认 `scheduledFor` 取路由参数 `?day=`（从哪天的列表点进来就加到哪天），
  没给就是待排池。
- 月历的「正在设定」开关：一个胶囊组（排期 / 最早可安排日），
  决定点格子写进哪个字段。切换时把当前值显示在月历上方，
  避免「点了却不知道改的是哪个」。
- 删除：**两步确认，不用 `Alert`**。`Alert.alert` 在 `react-native-web` 上是
  空实现（已核对 `react-native-web/dist/exports/Alert/index.js`：`static alert() {}`），
  用它在本项目的验证环境里就是「点了没反应」。
  实现：一个 `Chip`，点一下变成「真的删掉？」，再点一下执行。
- 删除前提示「有 N 项依赖它」：`task.remove` 会**静默清掉**别人的悬空依赖，
  这件事必须让学生看见再确认。
- 前置选择器**排除自己和自己的所有下游**（沿 `dependsOn` 反查的传递闭包）。
  不这么做的话，选错就是一句「校验失败：dependsOn 存在环」——技术上是拦住了，
  但那是让学生去解一道他并不知道题面的题。
- 路由：`/task/[id]` 与 `/task/new` 两个文件（静态路由优先于动态路由，
  实现时先跑一次确认匹配顺序；若不成立就退回单一路由 `/task/edit?id=`）。

## 3.8 顺手加固 `components/collapsible.tsx`

「调整」按钮失效还有一个**在这里排不掉**的可能：面板展开依赖 `onLayout` 量高度，
如果原生上它不触发，`contentH` 永远是 0，高度停在 0——表现和「按钮坏了」一模一样。
web 上它工作正常，所以探针证明不了它没问题。

加一个兜底：展开后若 300ms 内还没量到高度，就**放弃动画、直接把内容渲染出来**。

```tsx
const [measureFailed, setMeasureFailed] = useState(false);
// open 变 true 时起一个定时器；onLayout 真的报数就把定时器清掉
```

代价是最坏情况下没有展开动画，换来的是「它一定会打开」。
一个不带动画但打得开的面板，远好过一个漂亮但打不开的。

## 3.11 必须记下来的坑

1. **`Alert` 在 react-native-web 上是空实现**（已核对源码）。删除确认用两步内联。
2. **不要 Pressable 套 Pressable**：web 会冒泡、原生不会，两边行为不一致。
3. **新增路由后 `router.push('/calendar')` 会报 TS2345**，直到跑一次
   `expo start` 重新生成 `.expo/types/router.d.ts`（`expo export` **不**生成它）。
4. **`hitSlop` 会被父视图边界裁掉**：动作位的外层必须自己 ≥44pt。
5. **一次保存只发一条命令**（理由见 3.2）。
6. **`Id` 正则很严**：`^[a-z][a-z0-9_]{0,31}$`，生成器必须满足。
7. **两个视图的负载条基准必须同源**（`fullAt`），否则同一天会显示两种长度。
8. **月历必须周一起**，与 `startOfWeek` 同口径；否则周日会被放到最后一列，
   而中文语境里「本周」从周一开始。
9. 日历屏自己持有选中日，只在挂载时取 `today`，**不要**照抄今日页那条
   「`today` 一变就重置」的 effect——调试模式下改日期时，学生正在看的那天会被悄悄换掉。
10. **`Task.tags` / `plan.tags` 必须带 `.default([])`**，否则旧文件解析失败，
    而失败的表现是「设备上的计划文件无法解析」并暂停写入——学生会以为文件坏了。
11. **长按之后 `onPress` 不会触发**（两端都是这个规则），所以「点=展开、长按=编辑」
    不会双触发；但 e2e 里要**显式断言这一点**（第 5 步），否则哪天换了实现方式
    就成了「长按一下同时展开又跳页」。
