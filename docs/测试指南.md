## B. 命令行看引擎行为（不需要 Key）

```powershell
pnpm plan review examples/demo.studyplan --today 2026-10-19
pnpm plan advise examples/demo.studyplan --today 2026-10-19 --engine-only
```

**重点看这两处，它们是产品逻辑的核心**：

1. 「区间 DP 入门 3 题」**不应该**出现在重排建议里——它的 `pinned: true`，因为学生自己把它挪到了 10-26 避开期中考试周。
2. 每条建议的理由必须是具体的，例如 `从 2026-10-21 提前到 2026-10-19（按里程碑截止日与可用时段重新填充）`，而**不是**「为腾出容量重排到 X」。

**回报**：如果实际输出和上面两条描述不符，把输出贴给我。

## C. 接真实模型 🔑（最有价值的一步）

**不需要手打 env**——把配置写进仓库根目录的 `.env` 即可，脚本会自动加载。

```powershell
Copy-Item .env.example .env
notepad .env                                  # 填入 LLM_API_KEY，其余按你的端点改
pnpm plan advise examples/demo.studyplan --today 2026-10-19
```

需要一个 **OpenAI 兼容**端点。DeepSeek / Moonshot / 阿里百炼 / 硅基流动 / 本地 vLLM 都可以。

### `.env` 的加载规则（有 24 条测试守着）

| 规则 | 说明 |
|---|---|
| **向上查找** | 从当前目录逐级向上找 `.env`。所以 `pnpm plan`（根目录）、`pnpm --filter @sp/server start`（apps/server）、`node apps/server/src/index.ts`（根目录）都能找到同一个文件 |
| **真实环境变量优先** | CI 里注入了 `LLM_API_KEY` 时，`.env` 里的值会被忽略；命令会明确提示哪几个键被压住了 |
| **不打印值** | 只报告读到了哪些**键名**。`.env` 里有密钥，值绝不出现在日志里 |
| **空串等于未设置** | `LLM_API_KEY=` 这种占位会被当成没配，不会让人误以为配好了 |
| | `.env` 已在 `.gitignore` 里，不会被提交 |

> 如果控制台里中文显示成乱码（`閰嶇疆鏉ユ簮...`），先执行 `chcp 65001` 切到 UTF-8 代码页。
> 这是 Windows 终端编码问题，不是程序输出的问题。

**期望看到**：开头有一行 `· 已从 .env 读取 LLM_BASE_URL, LLM_API_KEY, LLM_MODEL`，
然后是一段 2–4 句的复盘综述，逐条理由标注 `[LLM]`。

**回报这五点**：

| # | 要回报什么 | 为什么重要 |
|---|---|---|
| 1 | 命令是否成功（exit 0） | 端点 / Key / 模型名是否正确 |
| 2 | 综述与逐条理由是 `[LLM]` 还是 `[引擎]` | `[引擎]` 说明降级了，note 里会写明原因 |
| 3 | note 里有没有「**已丢弃幻觉引用 N 条**」 | 模型编造 taskId / 选项的频率，直接决定我们要不要收紧提示词 |
| 4 | 大概耗时 | 超过 10 秒就要考虑加缓存或换更小的模型 |
| 5 | 理由读起来像不像人话 | **这是产品卖点**，模型写不好我们就得改提示词 |

## D. 服务端端点

`.env` 同样会被自动读取（在步骤 C 已配好）。

```powershell
node apps/server/src/index.ts
```

启动日志会明确写出**配置来源**，便于确认它读到的是哪个 `.env`：

```
[server] http://127.0.0.1:8787
[server] 配置来源：D:\...\programForCZW\.env
[server] LLM: deepseek-chat @ https://api.deepseek.com/v1
```

浏览器直接打开 `http://127.0.0.1:8787/` 会看到端点清单与 LLM 状态，**用来确认服务是活的**。

> ⚠️ **改了代码必须重启服务**，Node 不会热重载。
> 如果你看到的还是旧行为（比如根路径仍然 404），先确认端口上跑的是不是上一次启动的进程——
> 端口被占用时启动会明确报错，但因为请求会打到旧进程上，很容易被误判成「代码没生效」。

另开一个终端：

```powershell
node -e "const t=require('fs').readFileSync('examples/demo.studyplan','utf8');fetch('http://127.0.0.1:8787/plan/review',{method:'POST',headers:{'content-type':'application/json'},body:JSON.stringify({plan:t,today:'2026-10-19'})}).then(r=>r.json()).then(j=>console.log(j.note, j.view.narrativeSource, j.report.adjustments.length))"
```

**期望**：未配 LLM 时 `narrativeSource=engine`；配了 LLM 时 `narrativeSource=llm`。
`/health` 会如实报告 LLM 是否配置（**且不会泄露 Key**，有测试守着）。

**回报**：HTTP 状态码、`narrativeSource`、任何报错。

## E. 真机（Expo Go）

```powershell
pnpm --filter @sp/mobile start
```

手机装 Expo Go → 与电脑同一 Wi-Fi → 扫码。

⚠️ **注意**：四个正式界面**还没做**。现在只能验证「壳 + monorepo 解析链路」是否在真机上成立：
首页应显示 `Welcome to Expo`，并有一行 `Shared kernel  studyplan/v1`。

**回报**：

1. 有没有出现 `Shared kernel  studyplan/v1` 这一行（出现＝共享包在真机上解析成功）
2. 有没有红屏、白屏，或 `Unsupported SDK` 提示
3. 连不上时：Windows 防火墙是否放行了 Node 的**专用网络**

## F. 已知不需要测的

| 项 | 原因 |
|---|---|
| `pnpm install` 报 `ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY` | 已通过 `pnpm-workspace.yaml` 处理；若仍出现，加 `$env:CI='true'` 和 `--no-frozen-lockfile` |
| Explore 页图标在 Android 不显示 | 模板 demo 页用了 iOS 专有的 `expo-symbols`，那页会整个重写 |
| `examples/demo.studyplan` 被改坏 | 它同时是测试输入。要演练 `apply` 请先复制到 `.dev/scratch/` |
| LLM 三个变量只配一半 | 服务会**启动失败**并说明缺哪个。这是刻意的：否则服务能起来、每个请求都悄悄降级，而日志里看不出原因 |
