## v0.7 — 修掉那个只在真机上出现的 key 警告（2026-10-05）

你报的真机错误：

```
Each child in a list should have a unique "key" prop.
Check the render method of `RCTView`. It was passed a child from TalkScreen(./talk.tsx).
```

**跟「哪个 `.map` 忘了写 key」没关系** —— `talk.tsx` 里五处 `.map` 全都有 key。

### 真正的原因

`react-native` 的 `ScrollView` **无条件**执行一句
`children = React.Children.toArray(this.props.children)`（就在处理
`stickyHeaderIndices` 之前，RN 自己的注释还写着「这个函数会导致子节点 key 重排、
进而引起不必要的重挂载」）。

而 `React.Children.toArray` / `.map` 的实现（`react.development.js` 的 `mapIntoArray`）
在遇到**没有 key 的元素**时，会克隆一个新 key，**同时把克隆标成
`_store.validated = 2`**。Fabric 的 `warnForMissingKey` 的触发条件正是：

```js
(!child._store.validated && child.key == null) || child._store.validated === 2
```

**第二个分支就是为这个场景准备的。** 所以「没有 key 的直接子节点」在原生上必然报警告，
哪怕 `toArray` 已经给克隆补了 key。

### 为什么端到端和截图都没抓到

`react-native-web` 的 `ScrollView` 只在 `stickyHeaderIndices` / `pagingEnabled` 时
才调 `React.Children.map`——我们两样都没用。**所以这条警告在 web 上永远不会出现**，
截图、端到端、类型检查、单测四层验证**全都是隐形的**。

这一点比 bug 本身更值得记下来：我当时是逐行读 `ReactFabric-dev.js` 的警告条件
（那个 `validated === 2`）反查到 `react.development.js`，再反查到 RN 的 `ScrollView`。
从「某个 map 忘了 key」这个（错的）假设出发，会白走很久。

### 修法：把「记得加 key」换成「不用记得」

`app/` 下有十来个 `ScrollView`、几十个直接子节点，而且以后每加一个 `{}` 条件块都会
重新踩一次。所以收成一层 `ScrollBody`（`@/components/scroll-body`），
它就是 `ScrollView` 的直接替身，属性原样透传；10 个文件、11 处调用点全部换过去。

里面有一条**反直觉但关键**的约束：

> **补 key 不能用 `React.Children.map` / `toArray`——那正是把子节点标成 2 的那个操作。**

所以用普通数组的 `Array.map` + `cloneElement` 绕开它：没有 key 的补一个，
已经带 key 的原样放过（`.map` 出来的键是业务 id，比位置键好），
数组里套数组就往下走一层。

### 顺手补上一条「永远抓不到」的检查

`apps/mobile/test/scroll-body.test.mjs`：
`app/` 与 `components/` 里不许出现裸的 `<ScrollView>`（`scroll-body.tsx` 自己除外），
外加 `withChildKeys` 的契约。

**一个跑不起来的检查等于没有检查**，所以这条是**先验证过它会失败**的：
临时加一个用了 `ScrollView` 的文件 → 确认它报错 → 删掉。

### 迁移本身踩的坑（用 Python 也要数数）

批量改 10 个文件按全局约定用 Python（显式 `encoding='utf-8'` + `newline=''`）。
**第一版脚本摘 import 的正则少写了一个 `}`**（`[^}]*?` 匹配不到 `}`），
于是那一步**静默什么都没做**——而脚本只报「这个文件改了」（因为标签替换成功了），
看起来完全正常。改成**每一步都数次数**（换了几个标签、摘了几处、加了几处），
数目不对就非零退出。

批量改文件最怕的就是「部分成功」看起来像成功。

### 验证

- `pnpm typecheck` 干净；**670 个测试全绿**（shared 515 / server 84 /
  llm-client 27 / env-node 24 / storage-node 12 / **mobile 8**——mobile 这个包
  第一次有测试，就是上面那条静态检查）。
- **像素级证明这层是透明的**：`/goals` 与 `/` 两屏在替换前后截图
  **SHA256 逐字节相同**（`50117A19EA99C942` / `131AF236EBC793EB`），
  和 v0.3 抽取 `DayCell` 时用的是同一种证明方式。
- 端到端全过、无 console/page 错误。

## v0.6 — 目标卡片（2026-10-05）

对应需求：「把多目标显示做出来，也就是实现成目标卡片」。

**没有动文件格式。** 卡片要显示的每一项都来自现有字段
（`milestones[].{title,due,criteria,status}`、`tasks[]`、`competences[]`，加上引擎的
`milestoneRisk`）。唯一的例外是「判据逐条勾上了没」——`criteria` 是字符串数组、
没有勾选状态，所以这一版判据只作为文本展示；要能勾就得给格式加字段，那件事先问再说。

### 目标屏（`/goals`）：一条线一张卡

入口在今日页那句总目标的右上角，**带条数**（「目标 2」）——和「本周安排 ·〔日历〕」
同一个模式。条数本身就是今日页需要的那点信息量：它同时告诉你「这个计划不止一条线」。

卡片放**独立一屏**而不是堆在今日页：N 张卡竖排会把今天该做的任务推出屏幕，
而学生打开 App 十有八九是来干活的，不是来盘点的。

每张卡：名字 / 状态 / 截止日与还剩几天 / 进度条 / `2/7 项 · 已投入 3 小时 25 分 · 还剩 6 小时 25 分`。
**整块内容区点开**才显示细节——判据、能力点、排期区间（和任务卡同一个模式，
理由也一样：那个 26×22 小字的教训）。同时只展开一张。

排序是刻意的：**还在跑的在前、按截止日从近到远，已收尾的在后**
（还要注明「共 N 条」）。学生打开这一屏问的是「哪条线还在跑、哪条紧」，
不是「我历史上立过几条线」。

### 一屏一个强调色：主色给了风险

状态胶囊走**中性描边**（「进行中」不是语义色，是事实），
主色只出现在进度条上，而**风险**是唯一用填充的地方：

```
基础算法巩固
[进行中] [来不及 · 差 3 小时 25 分]      ← 唯一的语义色
11月30日 · 已过期 5 天                  ← 数字跟着变 warning
████████░░░░░░░░░░░░  2/7 项 · 已投入 3 小时 25 分 · 还剩 6 小时 25 分
```

全绿的屏上没有任何警告色，这本身就是信息。

### 三个「不骗人」的地方

1. **「排期 10月25日」这句话会骗人。** 一条线有两项任务、只排上一项时，
   它读起来像「这条线排好了」。所以卡片会补一句「还有 1 项在待排池」——
   待排池里那几项**不标明自己属于哪条线**，目标卡片是学生唯一能看见它的地方。
2. **没有证据的能力点不显示百分数。** 新目标的 `current` 是 0，而「0%」读起来
   像一句评价——系统其实只是还不知道。这种情况显示「还没有证据」。
3. **不属于任何一条线的任务要提一句。** `addTask` 造出来的任务（「跟 AI 说说」
   顺手加的那一项）本来就没有 `milestoneId`。不说的话，学生把卡片上的项数加起来
   会发现比计划里的总数少，而少掉的那些在这一屏上无迹可寻。

### 顺手补上：今日页的规划警告（v0.4 里漏掉的一条）

v0.4 的复盘页里写着「规划相关的警告（今日页也保留一份）」——**而今日页那份从来没做**。
这次补上，并且抽成一个共享组件 `PlanWarnings`，今日页 / 目标屏 / 复盘页三处
是**同一份实现**（同一件事在两处措辞不同是最容易被一眼看穿的拼装感）。

补的过程中撞出两个真问题：

1. **拿 `path` 当 React key 会撞。** 一项任务可以同时踩中好几条校验，
   而它们的 `path` 一模一样（`task:t_xx`）。上一版新加的「排期晚于它自己那条线的
   截止日」正好让这种情况变得容易发生：实测同一项任务能得到
   `task:t_dp00` 两条警告。而这个项目已经因为「拿警告文本当 key」炸过一次
   （见 §7 那段注释）。现在 key 是 `path#下标`，并且有一条共享层的用例钉住
   「同一个任务的几条警告会共用同一个 path」——那是界面必须知道的事。
2. **任务级警告没有主语。** 原来报的是「排期落在不可用区间 11-02~11-06」，
   而 `path` 里那个 `task:t_dp00` 学生看不见——他读到一句话，却不知道说的是哪一项，
   也就没法处理。提醒的价值全在「知道该动哪一项」，所以几条任务级警告
   （落进不可用区间、早于最早可安排日、排在前置之前、晚于总截止日、
   晚于那条线的截止日）现在都带上任务标题。

### 验证

- `pnpm typecheck` 干净；**662 个测试全绿**（shared 515 / server 84 /
  llm-client 27 / env-node 24 / storage-node 12）。
- 新增 `packages/shared/src/plan/goal-progress.test.ts`（19 条）：
  任务与投入按线分开算、排序、天数的三种情况（未到 / 今天 / 过期是负数不夹到 0）、
  已收尾的线不报过期、排期区间、悬在待排池的项数、没有证据的能力点、
  悬空引用不抛、风险只转达引擎说过的话。
- 端到端新增 6 条断言（放在最后，因为它要先重置成示例计划才有两条线）：
  今日页入口带条数、没有矛盾时提醒区整块不出现、目标屏两张卡、
  **展开才出现判据**、同时只展开一张、返回回到今日页。
- 截图看过四种状态：浅色 / 深色 / 展开 / **把时钟推到 12-05 之后的「来不及」态**
  （那一屏只有一个琥珀色，读起来就是「这条线要出事」）。

## v0.5 — 多目标：几条各自有截止日的线（2026-10-05）

对应需求：`功能补充与debug.md` 的「A 事件和 B 事件截止时间不一样，
但依旧要能用复盘排期」+「通过与 AI 对话新增目标并排期」。

**先说结论：引擎不用改。** 我把 `engine.ts`（469 行）从头读了一遍——
它**从来没有读过 `plan.goal`**（全文件只有 `proposeGoalOptions` 这个函数名里带 goal）。
它读的是 `tasks` / `milestones` / `competences` / `constraints`，排期时按
「所属里程碑的截止日」排序，也逐里程碑算「还来不来得及」。
**多目标这件事在引擎里早就是成立的**，缺的只是「怎么新增和修改一个目标」这条表达。

### 「目标」在数据里就是里程碑，没有加 `goals[]`

里程碑已经长着一个目标该有的全部东西：名字（`title`）、截止日（`due`）、
成功判据（`criteria`）、挂的能力点（`competenceIds`）、状态（`status`）。

- 加一个 `PlanFile.goals[]` 的话，同一件事要写两遍（目标和里程碑各自带截止日、
  各自挂能力点），而这个项目已经因为「两份真相」吃过两次亏
  （见 `docs/技术方案.md` §9.15 ⑧）。
- 语义上也站得住：学生说的「最终目标」是**一句话**，而赛事/考试是**几条并行的线**。
- 所以 `PlanFile.goal` 保持原样（那句话，复盘页要原样回显），
  多个目标住在 `milestones[]` 里，每个有自己的 `due`。
- **格式没动**，所以旧文件照常解析、不需要迁移、`SCHEMA_ID` 不变。

### 跟 AI 说说：新增一条线

学生说「我还想同时准备蓝桥杯，到十二月底」，AI 回一张卡：

> **新目标「蓝桥杯省赛」** · 截止 12月31日 · 3 项 · 合计 3 小时 15 分 · 排进 11/9–12/14

- 一条 `addMilestone` 提案带着**它的能力点和它的任务**，一条命令原子落地。
  拆成「先加目标、再加任务」的话，任务就得自己带 `milestoneId`——
  那正是模型最容易编错的地方（悬空引用会让下一次解析直接失败）。
- **模型不许算新任务的日期**：提示词要求把 `scheduledFor` 留成 null。
  日期由新增的 `placeNewTasks()` 把提案投影到一份计划**副本**上、跑一次
  `proposeReschedule` 算出来，再写回卡片。所以卡上那行日期是引擎排的，
  而且它同时就是「真的排进去了」的证据——排不下时那行会说「排不进现在的时段」，
  不假装成功。
- **日期填回那张卡，而不是另出一批排期卡**：一个目标 4 项任务如果各出一张卡，
  学生就能「留下 4 张排期卡、划掉那个目标」——而那些任务的 id 是随目标一起生成的，
  划掉目标之后它们根本不存在，整条命令会因为「未找到任务」被拒。
  填回同一条提案，划掉目标就是划掉它的一切，不存在半截状态；卡片数也保持在
  「一次新增 = 一张卡」这个量级。
- 目标清单以**人话**单独喂给模型（`id｜名字｜截止日`），因为计划原文里那是一坨 YAML，
  而多目标下模型最容易犯的错就是「该改某条线，它去改了总目标」。
  这一项由**服务端**从它本来就要解析的计划里填，客户端不用发。

### 复盘按每条线分开说

**修掉一个真错。** 原来检测到「某条里程碑来不及」时给出的卡，改的是
**总目标的截止日**（`goal.deadline + 14`）。总目标在明年四月、而紧的是十月中那条线时，
那张卡什么都没解决，卡片上却写着「里程碑可能赶不上」——比不给卡更坏。
还有更糟的一种：学生要是没填总截止日、只填了各条线的，`canExtend` 为 false，
于是**一张卡都不给**，而事实区已经在说来不及了。

现在：

- `milestoneRisk` 出的卡改的是**那条线自己的 `due`**；总目标那张卡只在
  「一个带截止日的目标都没有」或学生明确说要挪总截止日时才出现。
- 问句、事实、方向三处都**点名是哪条线**：「『蓝桥杯省赛』（12月31日 截止）可能赶不上」。
  多目标时只说「某个目标可能赶不上」，学生不知道指的是哪一条，也就没法在
  「挪截止日 / 少排一点 / 我自己想办法」之间做选择。
- 偏差文案不再打印 `m_base` 这种内部 id——那是给学生看的字。

### 两个顺手修掉的边界

- **排期视野不再永远 84 天。** `reviewPlan` 原来调 `proposeReschedule` 时没传 opts，
  于是视野永远是默认的 84 天。最远那条线在三个月之外时，引擎只在 84 天里找位置，
  找不到就把任务丢回待排池并说「未来 84 天内可用时段不足，排不下」——
  可 84 天之外明明还有大把时间。现在 `rescheduleHorizon()` 按
  **最远的那个截止日 + 14 天**算（下限 14、上限 730 天）。
- **校验补上「任务排到自己那条线的截止日之后」。** 原来只查 `goal.deadline`：
  总目标在明年四月、某条线的截止日在十一月底时，任务排到十二月什么都不报。
  现在逐里程碑查（`warn`，不是 `error`——排期是建议不是承诺）。

### 真机实测撞出来的一个坑：一个装饰性字段差点毁掉整条提案

第一次拿真实模型跑「新增目标」，结果是**一条提案都没有**，而且界面上什么都不显示。
把原始 JSON 打出来（`.dev/probe-talk-raw.mjs`）才看清：

模型给一个新增目标写了 6 条很好的任务，每条都带 `tags: ["搜索"]`——
它把「标记」理解成了**话题名**。而 `Task.tags` 存的是**标记目录的 id**
（`^[a-z][a-z0-9_]{0,31}$`），于是**整条 `addMilestone` 提案 schema 不过**：
一个目标连带 6 条任务全部消失。

两处修：

1. **`DraftTask.tags` 改成 `.catch([])`。** 一个装饰性标记不该有这种杀伤半径——
   标签丢掉，目标和任务照常进来。而且本地生成路径早有定论
   （见 `llm/planner.ts`）：标记由学生自己打，生成时不预设；
   模型给的「标记」十有八九是话题名，留着只会污染标记目录。
2. **schema 不过也要说话。** 那一层原来只 `dropped++` 就过去了，
   所以「一条都没有」和「都过不了」在界面上长得一模一样。
   现在会留下一条带字段路径的说明（`我没看懂这一条，先跳过了（estimateMin）`）——
   前面那句给学生，括号里给排查。

修完再跑，整条链路通了（下面是真实模型的输出）：

```
目标「搜索与贪心冲刺（校内选拔赛）」  截止 2026-12-28
  任务 6 项 · 合计 7 小时（模型把日期全留空）
   10-24(六) 60 分   OI Wiki：DFS/BFS/回溯 通读
   10-25(日) 90 分   回溯模板默写 + 5 道水题
   10-24(六) 45 分   OI Wiki 贪心：常见模型
   10-25(日) 90 分   贪心经典题 5 道
   10-28(三) 90 分   限时模拟
   10-31(六) 45 分   卡点复盘
应用：v5 → v6 · 3 条线 / 4 个能力点 / 15 项任务 · 校验零错误
```

日期全部落在学生说的空档（周一三五晚 + 周末上午）、避开了期中考试周，
**没有一个是模型编的**。

## v0.4 — 复盘与跟 AI 说说（2026-10-05）

对应需求：`功能补充与debug.md` 的「复盘／协商」那一组。
方案：`docs/复盘与AI协商方案.md`（逐条对过你的修正）。

这一版的主线只有一句：**计划不是一次生成就完了，它得能被改**。
前半是复盘（系统先说人话，再递上写好的卡片），后半是「跟 AI 说说」
（学生自己开一句口，含糊的先问清楚，做不到的明说）。

### 复盘：一屏六块，从上往下就是一次对话

点今日页右上角〔复盘〕进去。一屏从上到下：

1. **这周发生了什么** —— 本机算的事实：几项落后、几项超预估、几项比预期快、过了期的。
   这一段**不经过模型**，所以它可以先显示、也不可能被编。
2. **先问一句**（0–2 题，条件出现）—— 只在答案会改变建议时才问。没有可问的就整块不出现。
3. **我建议这样调** —— 先给**方向**（「下周 1 项换个日子、1 项时长调一下」）。
4. **帮你写好的卡片** —— 方向下面才是具体的那几张。
5. **现在的安排** —— 卡片区和日历，**和今日页是同一套组件**。
6. **之前的复盘** —— 折叠着的历史（过去几次的方向、改动、当时的回答）。

### 卡片是「帮你写好」，不是「替你做主」

- **不设条数上限**，典型 2–3 张。原来的「最多 5 张」是错的：上限只会让最后几条
  被砍掉，而学生并不知道少了什么。
- 每张卡可以**勾掉**（不要这条）、**划掉**（这次先不管）、**点进去改**（改成你想要的样子）。
- **点进去改的时候，预填的是「建议值」而不是「当前值」。** 这条最容易做错，
  做错了界面看着完全正常，只是每张卡点进去都是个没改动的表单，
  于是「帮你写好」这件事一点都没发生。所以端到端里专门有一条断言钉它。
- **卡片就是 `Proposal`**，和「跟 AI 说说」产出的是**同一个类型**，
  应用时走的也是**同一条命令**（`plan.applyAdjustments`）。
  两条路各写一套的话，「复盘能改的东西」和「跟 AI 能改的东西」迟早会不一样。

### 日期只能是今天和以后

复盘卡里出现过去的日期，是这一版唯一一次**真的差点出事**的 bug：
会话是用一个**过期的「今天」**建的（时钟还没连上，用的是设备日期），
于是卡片把 10/21 的任务「挪」到了 10/14。

现在有两道闸：`startReview()` 等 `storageReady` 才准开；
`reviewProposals()` 出来的每一张卡都再过一遍 `validateProposal`，
任何一张不过就**当场丢掉**而不是渲染出来。后者是兜底，
因为前者的时序依赖很容易在下次改动里被破坏。

### 跟 AI 说说：含糊就先问，做不到就说做不到

右下角常驻一个〔跟 AI 说说〕。一句话进去，三种结局：

- **说清楚了** → 回一张或多张待确认卡，勾了就应用。
- **说不清楚** → **先问**，最多 2 轮。这里原来是**没有上限的**：真机上模型连着
  问第二个问题、一个提案都不给，学生就卡在澄清里出不来了。
  上限是这一版的硬规则，而且**必须排在「有问题就不给提案」之前**——
  顺序写反的那一版，模型一个问题加一个提案时会**两样都丢**（测试抓到的）。
- **做不到**（比如要改不可用日期、要它替你决定报考哪个赛项）→
  **明说做不到**，并写清原因（`refusals`）。不是静默忽略，也不是假装改了个别的。

断网时**明说「现在用不了」**，并把手动入口（日历）摆在旁边。
没有做关键词兜底解析：那种「看起来在工作」的假成功比直接说不能更坏。

### 撤销：只活到下一次改动之前

应用完复盘建议，通知里带一个〔撤销〕。

- 撤销靠 `plan.restore` 装上应用前的快照，**不是**反向再发一条命令。
- **任何一次新的改动都会让〔撤销〕消失。** 这是刻意的：留着旧快照的话，
  学生会把中间那次改动一起撤掉——那不是他要的。
- 撤销本身也是一次**正常写入**（版本 +1），因为它确实改变了计划。

### 档案搬进了计划文件

`plan.profile`：目标、截止日、水平、每周可投入时间、方便的学习日、薄弱点、
要避开的整段日期。

- **它不是设备上的设置，而是文件里的一段。** 重开 App 它还在；换设备、
  把文件发给同学，上下文跟着走；「跟 AI 说说」和找资料都有依据，
  不必每次从任务表反推。
- **校验不过就当没有**，不让一份坏档案把整份计划读不出来——
  学生亲手写的任务比一段背景描述重要得多。
- 这一版把两处「两份真相」的漂移修掉了：`installPlan` 不传档案时原来是
  「保持原样」，`apply` 之后完全不更新镜像。表现是文件页写着「还没有档案」，
  而正下方那坨文件正文里就写着档案。现在镜像一律 `readProfile(plan)` 重新读。

### 入口和位置解耦

〔复盘〕的入口是 `<ReviewEntry />` + `useReviewLauncher()`，
「跟 AI 说说」是 `<TalkEntry />` + `useTalkLauncher()`。
你说过这个按钮的位置随时可能要改，所以组件本身**不假设自己在哪**：
要挪就挪一行 JSX，不用动逻辑。手动触发和（将来的）主动提示
**共用同一个 `openReview()`**，不写没人调用的函数。

「重做访谈」从今日页右上角挪到了文件页的「演示用」区——它是个演示动作，
原来占着那个位置，把真正属于用户的动作（复盘）挤掉了。

### 这一轮明确不做

主动提示复盘（只留位置）、流式思考链、语音输入、跨会话聊天记忆
（跨会话的「记忆」靠 `plan.profile`，不靠聊天记录）。

### 验证

- `pnpm typecheck` 干净；**620 个测试全绿**（shared 473 / server 84 /
  llm-client 27 / env-node 24 / storage-node 12）。
- 端到端新增（并在离线与真机两条路径上都过了）：
  复盘入口常驻、六块都渲染、0 张卡和 0 题两个分支、
  **编辑建议卡预填的是建议值**、应用只 +1 版、
  撤销后回到应用前且再改动一次后〔撤销〕消失、
  含糊的话给的是问题而不是提案、做不到的出现 `refusals`、
  断网时 /talk 说连不上而 /review 仍能走完、
  **刷新后学生档案还在**（内存镜像已随刷新清零，那份只能是从文件里读回来的）。
- 真机实测 `/plan/talk` 打到真实模型：会拒绝猜、会用具体任务 id 和日期问、
  会给「我说顺嘴了」这种退路。

### 一个反复出现的坑（第四次踩，这次代价最大）

**不要用 PowerShell 的 `Get-Content -Raw` + `Set-Content` 改写源码文件。**

这一轮毁掉的是 `apps/mobile/src/state/plan-store.tsx`（1277 行，store 的全部逻辑）：
中文变乱码、换行丢了一百多个、文件当场不是合法 UTF-8。
而且**这次没有退路**——git 仓库还停在 v0.3 之前（`b987b93 init`，
那份文件只有 521 行），没有 stash，打包产物里没有 sourcemap，
VS Code 的本地历史里一条记录都没有。

最后是拿 v0.2 那份基线**整份重写**再加回 v0.3/v0.4 的全部改动，
然后靠 `pnpm typecheck` + 整条端到端把它验回来。
代价是这一轮里最贵的一次，而且完全可以避免：改源码一律用编辑工具。

## v0.3 — 日历与任务编辑（2026-10-05）

对应需求：`功能补充与debug.md` 的「主界面交互性弱的问题」。
方案：`docs/日历与任务编辑方案.md`。

### 日历：整份计划排成什么样

今日页「本周安排」右边多了〔日历〕，点进独立一屏。

- **月历和首页周条是同一个组件**（`components/day-cell.tsx`）。不是照着画一遍——
  两处各写一遍必然长歪，而「两个视图对同一件事说法不同」在这个项目里已经吃过一次亏。
  差别只有一处：周条上那行「周几」在月历里由列头承担。
  **负载条的满格基准也和周条同源**，否则同一个学生在同一天会看到两种长度，
  而长度是这一屏唯一的信息载体。
- **固定 42 格（6 行）**，不做「够用就少一行」：行数一变整屏高度就跳，
  而学生在日历上做的就是前后翻月份。
- **周一为一周之首**，与「本周」的口径一致。超过本月的补格压暗但仍可点
  （那些日子上的任务是真的），点它会**连带翻到那个月**，否则会出现
  「选中了 11 月 2 日、网格却是 10 月」这种自相矛盾的状态。
- **没排期的任务不画进日历**。日历的横轴是日期，把没有日期的任务塞进某一天
  是在撒谎；它们只在底部用一行说明提一句。

### 任务卡：点开、长按改

- 那个 **26×22 的浅色「调整」小字删掉了**。现在**整块内容区**
  （标题 + 胶囊 + 备注）就是展开/收起按钮，高度远超 44。
- **勾选框是它的兄弟，不是子元素**。`Pressable` 套 `Pressable` 在
  react-native-web 上点击会冒泡、在原生上靠 responder 系统，两边行为不一致；
  放到外层，嵌套这件事在构造上就不存在——点勾选框只会勾选。
- **长按整块内容区 = 进编辑页**。两个手势不会互相误触发：
  RNW 的 `PressResponder` 里长按之后不调 `onPress`，原生同规则（都有测试/探针盯着）。
- 右边是一个**会转 180° 的折角箭头**（只动 transform，走原生驱动），它只是提示。
- 展开区第一行是「编辑这一项」。**这不是多余的**：长按对读屏用户完全不可见，
  一个只有长按的入口等于没有入口。

### 编辑页：一切点选，不让你敲日期

一条硬规则：**除了标题和备注，这一屏没有任何自由文本输入。**

- **选日期用月历点**，而且和日历屏是同一个 `CalendarPanel`。
  「最早可安排日」也用它——上面一个「正在设定：排期 / 最早可安排日」的开关决定
  点下去写进哪个字段。一张月历 + 一个开关，比两个分开的控件好理解，
  也少了一个要单独校验的输入。
- **时长**：档位胶囊 + `±15` 微调，当前值大字显示。档位之外的分钟数也能设，
  但仍然不用打字。
- **前置**选择器**排除自己和自己的所有下游**。不排除的话，选错就是一句
  「校验失败：dependsOn 存在环」——技术上是拦住了，但那是让学生去解一道
  他并不知道题面的题。
- **删除是两步确认，刻意不用 `Alert`**：它在 react-native-web 上是空实现
  （`static alert() {}`），而本项目的截图和端到端验证全在 web 上跑，
  用它就等于「点了没反应」。删除前还会说清楚有几项以它为前置。

### 一次保存 = 一条命令

改动攒在本地草稿里，点「保存」才发**一条** `task.edit`。

取消版本管理之后，这个决定**变得更硬**了：拆成四条的话，中间任何一条被拒
（字段非法、前置成环）都会让前面几条已经生效，而**现在没有回滚可以把这一次编辑
整体撤掉**——学生看到的是「标题改了、日期没改」，得自己想起来改了哪几处。
一条命令则是要么全成要么全不成。

顺带两个次要理由：一次编辑在 history 里变成四行，回放时看不出这是一次动作；
以及一次编辑会打四遍写盘和四份 `versions/` 快照。

### 标记：只搭框架，实现尽量简单

学生可以给任务打〔重点〕〔等考完再做〕〔想问老师〕〔易错〕，卡片上看得见。

- **任务上存的是标记 id，不是文字**（`task.tags: ['tag_focus']`）。
  这是整个框架的全部意义：以后要加「时间标记（影响排期）」或「标记自定义颜色」，
  改的是**标记目录**和引擎，**任务上的数据一个字都不用动**。
- **不升 schema 版本**：`Task.tags` 和 `PlanFile.tags` 都带 `.default([])`，
  所以旧文件照常解析，不需要迁移。这一点不是「应该没问题」——新增了
  `describe('格式演进：只加可选字段')`，用一份**手写的、没有 tags 的旧文件**
  证明它读得进来（刻意不用示例文件当样本：那份文件以后可能被补上 tags，
  用例就悄悄失去意义了）。
- **故意没有加** `kind: 'time'` / `payload` 这类预留字段。今天没有任何代码会读它们，
  而一个永远不被读的字段是最容易腐烂的东西。扩展点是「任务存 id」这件事，
  不是空字段。

### 顺手修了一个既有 bug

`task.edit` 原来只有一句 `Object.assign(t, cmd.patch)`，**没有任何字段校验**，
而 `validatePlan` 不管字段合法性（它管引用、环、周预算、档期冲突）。于是
`patch: { title: '' }` 会 `ok: true` 地写进磁盘，**下一次启动解析这份文件就失败**，
界面变成「设备上的计划文件无法解析」并进入暂停写入的保护状态。

在这之前它是潜伏的——**没有任何界面调用 `task.edit`**，所以踩不到。
编辑页是第一个调用者，而它一定会允许学生把标题删空。现在走整条
`Task.safeParse`，一次覆盖全部字段。

### 布局变化

- 区块标题行现在是 **44 高**（动作位必须是 44pt 触控区）。标题到自己的内容 24.5pt、
  到上一个区块 36.5pt，所以标题仍然**跟着自己的内容**，没有散掉。
- 今日页多了两个动作：[本周安排] 右边〔日历〕、[选中那天] 右边〔+ 新任务〕。
- 新增两屏：`/calendar`、`/task/[id]`（`/task/new` 会落到同一条动态路由上）。

### 验证

- `pnpm typecheck` 干净；**526 个测试全绿**（+91：日历 24 / id 12 / 标记 17 /
  字段差分 24 / 命令层与格式 14）。
- **抽取没改动一个像素**：`.dev/shot.mjs` 按语义定位周条的七个格子并裁图，
  改动前后两张裁图 **SHA256 逐字节相同**（`1DE7E98E3D1833C6`）。
- **长按与单击的对照**（这是最容易写错的地方）：
  长按 700ms → 进编辑页、**处于展开状态的卡片 0 个**；单击 → 留在今日页、
  **展开 1 个**。
- **保存链路真的写回去了**：长按 → 打标记 → 保存 → `v5 → v6`（一次编辑只推一版）、
  通知「任务「…」已修改」、卡上出现〔重点〕。
- 端到端全过、无 console/page 错误，新增断言：月历 42 格、第一格是周一、
  翻月能翻回来、点「14 日」下面换成那天、日历能进能回。

### 三个坑

1. **`expo start` 生成的路由类型可能是错的，要加 `--clear`。** 加新目录
   （`src/app/task/`）时踩到：生成出来的清单把 `src/components/*` 和
   `packages/shared/src/plan/*` **当成了路由**，而 `/task/[id]` 不在里面。
   清缓存重来才干净。
2. **端到端的结账断言其实依赖「今天是周几」。** 那天恰好是周一，而访谈里学生只勾了
   「周一晚上」——生成计划把所有任务都排到了今天，正好落在结算区间**左开的端点之外**
   （「上次打开那天不算欠账」是设计如此），窗口里一项都没有。修法是先新建一项排到明天，
   与星期几无关。
3. **手机上那条「Cannot connect to Expo CLI」是开发期的 HMR 警告**，说的是
   Fast Refresh 的 websocket，不是 App 出错。查的时候还发现：**这台机器访问自己的
   局域网地址就是不通**（`192.168.3.18` 上 8081 和 8787 从本机都超时，
   连一个什么都没监听的端口也超时；Node 和 PowerShell 一样）。
   所以「从本机探局域网地址」**不能当判据**——一个会误报的检查比没有检查更坏。
   `pnpm mobile` 现在探的是**回环**（这条才是实打实的），局域网那条只做参考并说明原因。

## v0.2 — 时钟与回归结账（2026-10-04）

对应需求：`功能补充与debug.md` 的「时间显示问题」。
方案：`docs/时钟与回归补账方案.md`（第二部分是 A 的详细设计；
第一部分 B 的用户视角效果在 v0.4 实现，细化方案见 `docs/复盘与AI协商方案.md`）。

### 时间不再是一个写死的常量

之前「今天」是 `DEMO_TODAY = '2026-10-19'` 这个写死的常量，命令时间戳来自一个
从示例计划时间戳起步的假游标。那是被逼出来的：命令层当时有一条硬规则
「命令时间晚于计划更新时间才接受」，而示例计划的时间是演示口径，
真实系统时间早于它，于是**每一条命令都会被挡掉**——界面表现就是「点了没反应」，
而且看不出原因。

现在：

- **两种模式，显式二选一。** 调试模式的日期由设置给，想设哪天设哪天，而且
  **不会自己走**（要前进就手填一个新日期）；正常模式的日期由服务端给，
  回到前台重新对表。
- **服务端有了唯一的时钟**（`GET /time`）。在这之前同一个「今天」在项目里有
  四个来源：客户端一个常量、`routes/plan.ts` 一份、`routes/interview.ts` 一份、
  `codeforces.ts` 里的 `Date.now()`。它们真的打过一次架——演示日期是 2026-10-19，
  实时赛程却按真实的 2026-10-04 过滤，抓回来的每一场都显示成「已截止 12 天」。
- **「今天是哪天」由服务端算好再给。** 客户端永远不做「UTC 时刻换算成本地日期」
  这件事——`toISOString().slice(0, 10)` 在东八区晚上 8 点之后会算成「明天」。
- **`SP_TODAY` / `SP_TZ`**：把整台服务端的时间冻结在指定的一天，演示和调试用。
  不设就是真实时间。
- **拆掉了那条时间守卫。** 现在没有任何地方需要它（客户端是同步 reducer；
  服务端生成的计划走 `installPlan`，根本不经过命令层）。所以是删掉，
  而不是换一个「命令带期望版本号」的替代品——那个字段永远不会被触发。
- **顺带修了一个真的乱序写**：生成一份计划要 20–40 秒，学生在这期间打勾、
  改时长，`installPlan` 回来时会**静默覆盖**他的修改。现在会比对修订号，
  不一致就拒绝装入并说明原因。

### 隔了几天再打开，系统会自己发现

新增**结账页**（`/settle`）。启动时如果距上次打开 ≥1 天、而且确实有任务过期，
就自动进去。

- **默认值是「都没做」**，学生只勾出其实完成了的那几项。这个默认是无损的，
  而且让最常见的情况是**零次额外操作**；反过来「逐项问做了没」在隔了 5 天、
  9 项时会变成 9 次问答。
- **一条命令，不是十二条。** `plan.settle` 一次结算 = 一次版本 +1 + 一条历史 +
  一个回滚点。十二项各发一条会得到十二个版本，而且一次回滚回不到整批之前。
- **「放弃」用 `skipped` 而不是物理删除**：删掉会让「学生主动放弃」和
  「这项从来没存在过」变成同一件事，而它们在复盘时是完全不同的信息。
- **兜底先说人话，模型后润色。** 叙述先显示本机算出来的那版，模型返回后再换上去。
- **模型不许改数字。** 服务端拿白名单核对它写出的每一个整数，出现白名单之外的
  数字就整段退回本机叙述。光在提示词里写「不要改数字」是没有约束力的，
  而「有 9 项没做」是这一屏唯一不能错的数字。
- **调试模式下的「今天」不能自己走**，否则「模拟隔了 5 天」就成了一个
  会自己消失的状态，演示没法依赖它。文件页有〔模拟隔了 5 天回来〕，
  它同时是演示开关和这条链路的测试入口。

### 去掉了版本管理界面

按「交互要简洁」的要求，删掉了版本历史页和回滚入口。
`saveWithSnapshot` 仍然在写——它是写盘时留一份上一版的安全网，
删掉它反而是折腾。计划文件里的 `versions/` 目录还是可以直接打开手动恢复的。

### 一个反复出现的坑（第二次踩）

**不要用 PowerShell 的 `Get-Content -Raw` + `Set-Content` 改写源码文件。**
中文会被按错误编码回写，文件当场变成非法 UTF-8。这一轮在 `settle.tsx` 上又中了一次，
只能整份重写。改源码一律用编辑工具。
